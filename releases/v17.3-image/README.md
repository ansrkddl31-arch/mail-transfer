# EX메일 익스플로러 v17.3 · 이미지 자동 전송4

v17.2 릴리즈의 화면과 메일·첨부·AI 요약·일정 기능을 유지하고 자료교환 전송 경로를 교체했습니다. 사용자 PC에서 ＋·파일 선택·보내기·반대편 수신까지 확인한 이미지 시험 v3의 매칭 코드와 전송 제어를 앱에 연결했습니다.

## 이미지 자동 전송4 수정

**로그인하고 불러오기** 한 번으로 첫 연결·공개키 교환 후 수집까지 이어갑니다. 외부에서 이미 로그인했으면 세션을 재사용하고, 로그인이 필요하다는 응답일 때만 로그인 창을 띄웁니다. 앱을 켜는 것만으로 연결하거나 수집하지 않습니다. 초기화는 다음 요청 전까지 대기합니다. `tests/first-collection.ps1`로 조기·중복 응답, 잘못된 키, 시간 초과, 중지·초기화 후 늦은 응답과 연결 재사용을 검사합니다.

앱이 사용하는 수신 폴더·역할별 작업 폴더·outbox의 생성 시험 TXT를 사용 후 약 1분 뒤 정리합니다. MailTransfer-Probe 및 EXMail-ImageTrial 파일명뿐 아니라 고유 ID와 실제 시험 문구까지 일치해야 하며, 다른 내용의 TXT는 삭제하지 않습니다. 보내는 중이거나 파일이 잠겨 있으면 미루고 다시 확인합니다. 수신 시험 파일의 ID·해시는 진단용 마지막 수신 기록 한 개로 남깁니다. 앱 폴더 밖의 예전 독립 시험 도구 logs는 전체 디스크를 검색해 지우지 않습니다.

프로그램 실행 후 자료교환 파일이 들어온 직후 새로 열린 **설정된 수신 폴더** Explorer 창만 닫습니다. 이미 열려 있던 창·다른 경로·여러 탭이 확인되는 창은 유지합니다. 실제 Windows Shell COM 창 닫기는 개발 환경에서 실행하지 않았으며 조건 판정은 테스트 대역으로 검사했습니다.

첨부파일 자동 삭제를 제거했습니다. 외부 전송 대기본·내부 수신 폴더의 전송본·내부 원래 이름으로 보관하는 첨부 모두 유지합니다. 기존 요청/결과 메시지의 완료 후 정리는 유지합니다.

`pwsh -NoProfile -File tests/maintenance.ps1`로 생성 프로브 검증·유예·파일 잠금·첨부 보존과 폴더 창 선택 조건을 검사합니다.

## 이미지 자동 전송3 수정

웹메일의 ‘최종사용정보/접속 아이피 변경’ 네이티브 알림을 정확한 문구와 mail.ex.co.kr HTTPS 주소로 식별해 확인하고 수집을 이어갑니다. 다른 알림·확인창·인증창은 자동 수락하지 않으며 사용자 확인이 필요하다는 오류를 반환합니다. 비밀번호 오류 반환은 유지합니다. 알림 내용·아이피를 로그에 쓰지 않습니다.

자료교환은 클릭하기 전 두 화면 연속으로 대상 버튼과 파일명을 확인합니다. 화면이 잠시 안 보이거나 버튼이 이동하면 제한된 횟수 안에서 **클릭 전 확인만** 다시 합니다. 보내기를 한 번 누른 뒤에는 이 확인 루프로 돌아가지 않습니다. 다른 창이 가리면 알려진 자료교환 창을 최대 두 번 복원하고 다시 캡처합니다. 실패 로그에는 등록 파일 확인 여부와 마지막 후보가 남습니다.

`python tests/mail-notice-cdp.py`는 로컬 WebSocket fixture에 실제 PowerShell CDP 수신 코드를 연결해 정보 알림 처리 후 명령 재개·미등록 알림/다른 출처/확인창 수락 방지·비밀번호 오류 반환을 검사합니다. 실제 외부 웹메일 로그인은 이 개발 환경에서 실행하지 않았습니다.

## 이미지 자동 전송2 수정

내부망의 파란색 보내기와 외부망의 청록색 보내기를 모두 인식합니다. 보내기와 짝을 이루는 왼쪽 회색 취소 버튼도 인식합니다. 이미지에서 찾지 못한 버튼은 네이티브 버튼 이름·위치로 보완합니다(UI Automation 아님). 등록 파일명은 전체 고유 ID가 일치하는 파일명·확장자가 숨겨진 파일명·전체 경로를 허용합니다.

앱 하단 버전 표시는 **앱 v17.3 · 이미지4**입니다.

## 설치와 설정

1. 내부·외부 PC 모두 기존 EX메일 PowerShell을 종료합니다. 브라우저 탭만 닫으면 기존 프로그램은 계속 실행됩니다.
2. 양쪽에서 이 배포본의 자동설치 BAT를 실행합니다. `C:\EX메일 익스플로러`에 설치하며 기존 설정·메일·일정 파일은 덮어쓰지 않습니다. 바탕화면 바로가기와 `EXMail-Recover.bat` 시작프로그램 등록을 유지합니다.
3. 내부·외부 역할과 각 PC의 실제 자료교환 **수신 폴더**만 지정하세요. 버튼 좌표나 화면 배율을 저장하지 않습니다.
4. 양쪽 자료교환 프로그램에 로그인해 두세요. 내부에서 **로그인하고 불러오기** 한 번만 누릅니다. 첫 요청에 연결·공개키 교환을 마친 뒤 자동으로 수집하며, 준비된 연결은 앱 실행 중 재사용합니다. 설정의 **연결 초기화**는 대기와 연결만 지우고, 다음 수집 때 다시 연결합니다. 설정의 **이미지 자동 인식 · 시험 전송**은 선택 사항이며, 누르면 시험 TXT 한 개가 실제 전송됩니다.

자료교환 창이 닫혀 있으면 기존 실행 경로 저장·검색 기능으로 열거나 복원합니다. 실행 위치를 하나로 찾을 수 없으면 임의의 EXE 선택창을 띄우지 않고 중지하므로, 자료교환을 직접 열고 다시 시도하세요. 자료교환 자체의 로그인·잠금 화면은 사용자가 처리해야 합니다.

## 전송 동작

내부 요청 TXT, 외부 결과 TXT, 첨부 전송과 시험 전송에 모두 같은 이미지 전송 경로를 적용합니다. 저장된 sender-settings.json 좌표는 읽지 않습니다. ＋와 보내기 후보를 매번 확인하고, 기존 네이티브 파일 선택창 처리로 전체 경로를 입력·검증합니다. 등록된 고유 전송 파일명도 확인한 후 보내기를 한 번만 누릅니다. UI Automation으로 버튼을 읽지 않습니다.

보내기 목록에 기존 파일이 남아 있으면 하단 취소를 한 번 눌러 초기 ＋ 화면으로 복귀한 뒤 이번 파일을 새로 등록합니다. 취소 버튼을 유일하게 확인하고, 초기 화면 복귀까지 확인해야 다음 단계로 넘어갑니다. 보내기를 이미 시도한 뒤에는 목록을 자동 취소하거나 재전송하지 않습니다.

전송 직전부터 기존 입력 제한과 F4 중지를 사용합니다. 주입된 자동화 클릭·Enter는 허용합니다. 보내기를 누른 뒤 결과가 불명확하면 자동 재전송하지 않습니다. 화면의 빈 목록 복귀는 송신 UI 확인이며, 실제 도착은 기존 반대편 폴더 감시·응답 처리로 확인합니다.

성공 여부·오류 코드는 기존 .send.json, 전송 단계, logs/MailTransfer-Send-…txt에 기록합니다. 실패 시 마지막 화면과 후보 좌표·단계를 logs/ImageTransfer-last-error.png 및 .json에 덮어써 남깁니다. 성공 화면은 파일로 쌓지 않습니다. 오류 화면에는 자료교환 사용자명·파일명 등이 포함될 수 있으므로 공유 전에 확인하세요. 모양이 바뀌거나 후보가 모호하면 클릭하지 않습니다. 다른 PC·배율에서도 시험 전송으로 확인할 수 있습니다.

## 빌드와 검증

`python build.py`로 설치 HTML·BAT·프로그램 ZIP·전체 소스 ZIP을 생성합니다. 35개 프로그램 파일을 포함합니다. 설치 HTML을 여는 것만으로 BAT가 실행되지는 않습니다.

Node.js와 jsdom 24.1.3으로 `node tests/runtime-ui.cjs`와 `node tests/setup-popup.cjs`를 실행합니다. PowerShell 7에서 `tests/image-integration.ps1`, `tests/startup.ps1`을 실행합니다. Linux에서는 존재하는 쓰기 가능한 XDG_CACHE_HOME, XDG_CONFIG_HOME, XDG_DATA_HOME을 지정하세요.

`tests/image-flow.ps1`, `tests/image-detector.ps1`은 실제 배포 모듈의 실패·중지 제어와 매칭 코드를 검사합니다. Python websockets·Chromium·PowerShell 7이 있으면 `PWSH=/path/to/pwsh python tests/packaged-browser.py`로 최종 HTML에서 추출한 프로그램의 실제 HTTP·브라우저 동작을 확인할 수 있습니다. 이 검사는 최초 자동 시험 전송이 없고, 폴더 저장 후 완료가 가능하며, 선택 시험 전송 버튼이 올바른 서버 경로를 호출하는지 확인합니다. 실제 Windows 전송 프로세스 실행만 테스트 대역으로 대체합니다.

사용자 PC에서 별도 이미지 시험 도구의 실제 전송·수신은 확인됐습니다. 통합 앱에서는 원래 UI·페이징·AI·일정 회귀, 좌표 파일 없는 송신 어댑터, 성공·중지·불명확한 전송 결과, 파일 검증, 입력 제한 정책, 설치·복구를 모의 검사합니다. 실제 Windows 통합 앱의 입력 훅·창 복원·전송과 재부팅은 이 Linux 환경에서 실행하지 않았으며 양쪽 PC에서 최종 확인해야 합니다. 기존 v18.2 AI 웹 질의 기능을 추가한 배포본은 아닙니다.
