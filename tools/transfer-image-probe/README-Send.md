# 자료교환 이미지 자동 전송 시험 v2

**시험 TXT 1개를 실제로 전송하는 별도 시험 도구입니다.** 기존 EX메일 앱에는 아직 적용하지 않았습니다. 진단 v1에서 이 PC의 ＋·보내기 위치 인식이 확인된 뒤 사용하는 단계입니다.

## 실행

1. ZIP을 새 폴더에 풉니다. 자료교환 앱을 켜고 **보내기 목록을 비웁니다.** EX메일 앱에서 다른 전송 작업을 동시에 진행하지 마세요.
2. `이미지전송시험.bat`를 실행합니다.
3. **8초 안에 자료교환 창을 클릭**한 뒤 기다립니다. 마우스·키보드를 사용하지 마세요. 중지는 **F4**입니다(화면 캡처/짧은 네이티브 호출이 끝나는 확인 지점에서 처리).
4. ＋ 인식·클릭 → 새 TXT의 전체 경로 입력·열기 → 고유 시험 파일명 확인 → 보내기 1회 → 빈 목록 복귀 확인 순서로 실행합니다.
5. 열린 logs/send-… 폴더의 `result.json`과 반대편 수신 여부를 확인합니다. 반대편에는 `EXMail-ImageTrial-고유ID.txt`가 도착해야 합니다. 이 파일에는 식별자와 시험 문구만 들어 있습니다.

전송 성공 여부가 불분명하면 **바로 다시 실행하지 말고 반대편부터 확인**하세요. 같은 실행에서 보내기를 재클릭하지 않습니다. F4나 오류로 멈추면 선택창·등록된 파일이 남을 수 있으므로 확인 후 직접 닫거나 등록 취소하세요. 시험 후 양쪽 시험 TXT와 로컬 logs 폴더는 직접 지울 수 있습니다.

## 결과

- `SEND_LIST_EMPTY_RECEIPT_NOT_VERIFIED`: 보내기 클릭 후 빈 목록이 두 번 연속 관찰됐습니다. **반대편 수신은 별도 확인해야 합니다.**
- `STOPPED_OR_UNCONFIRMED`: 실패 또는 중지입니다. `stage`, `error`, `sendAttempted`, `sendClicks`를 확인하세요. 실제 클릭 시도 후에는 전송됐을 가능성이 있어 자동 재전송하지 않습니다.
- 후보 중복·화면 이동·다른 창의 가림·앞창 변경·시험 파일명 미확인 시 중지합니다. 파일명은 기존 네이티브 컨트롤 읽기 방식으로 확인합니다. UI Automation은 사용하지 않습니다. 해당 컨트롤을 읽을 수 없는 환경에서는 전송하지 않고 로그를 남깁니다.

로그의 screen-N.png에는 자료교환 창의 사용자명·파일명·받기 목록이 포함될 수 있습니다. 자동 업로드는 하지 않습니다. 공유 전 필요한 부분을 가리세요. 스크린샷은 실행당 최대 30장입니다.

`이미지인식진단.bat`도 함께 포함했습니다. 이 BAT는 기존처럼 후보 표시만 수행하며 클릭하지 않습니다.

## 검증 범위

실제 사용자가 제공한 420×640 화면에서 ＋ 후보 1개, 보내기 후보 1개가 올바르게 표시됐습니다. 매칭 코드의 합성 이미지 100·125·150% 크기 시험과 전송 제어 코드의 정상·중복 후보·파일명 불일치·보내기 미발견·결과 불명·F4·클릭 오류 시나리오를 검사했습니다.

Windows 화면 제어·파일 선택·실제 i-oneNet 전송은 이 개발 환경에서 실행하지 않았습니다. 이 ZIP으로 그 구간을 시험합니다. 현재 보내기 인식은 청록색·사각형 모양에 근거하며 글자 OCR이 아닙니다. 기존 앱 배포본과 시작프로그램은 수정하지 않습니다.
