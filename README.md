# EX메일 익스플로러

현재 배포본은 **[v17.3 이미지 자동 전송](releases/v17.3-image/README.md)**입니다. 사용자가 지정한 v17.2 릴리즈 UI를 유지하고, 실제 PC에서 전송·수신을 확인한 이미지 인식을 앱에 연결했습니다. 자료교환 버튼 좌표 설정은 필요하지 않으며 역할·수신 폴더 설정은 유지합니다.

설치 HTML·자동설치 BAT·프로그램 ZIP·소스 ZIP은 `releases/v17.3-image/dist/`에 있습니다. 빌드는 `python releases/v17.3-image/build.py`를 사용하세요. 과거 배포본과 복원 기록은 보존합니다.

## v18.2-r1 복원 기록

사용자 제공 v18.2 자동설치 BAT의 내장 ZIP에서 34개 프로그램 파일을 복원한 수정판입니다. v17.2로 되돌리지 않았습니다. 최초 복원 커밋 `149178c`는 원본 프로그램 바이트를 보존합니다.

## 설치와 사용

**내부 PC와 외부 PC에 각각 설치해야 합니다.** 기존 EX메일 PowerShell 창을 종료하고 설치 HTML에서 자동설치 BAT를 다운로드하여 실행하세요. HTML을 여는 것만으로는 설치되지 않습니다.

1. `C:\EX메일 익스플로러`에 프로그램을 저장하고 바탕화면 바로가기와 사용자 시작프로그램을 등록합니다. 설치가 끝나면 앱을 엽니다.
2. 양쪽에서 PC 역할과 실제 자료교환 수신 폴더를 지정합니다. 초기 위치 설정 안내의 **시작**을 누르면 기존 위치 설정·테스트 전송을 실행합니다. 수신 폴더가 미확정이면 먼저 폴더를 설정합니다. 이 테스트는 실제 시험 파일 하나를 전송합니다.
3. 외부 PC는 대기 상태로 두고, 내부에서 **외부 연결**을 누릅니다. 연결 후 로그인·수집과 AI 요청을 사용할 수 있습니다. 웹메일·AI의 추가 인증은 외부 PC에서 직접 완료합니다.

## 이번 수정

- 자료교환 위치 미설정 시 안내 팝업을 표시하고 시작 버튼을 기존 설정 프로세스에 연결했습니다. 나중에를 누르면 같은 역할에서 반복 안내하지 않습니다.
- 사용자 시작프로그램의 `EXMail-Recover.bat`에 설치 데이터를 내장했습니다. 정상 파일은 그대로 사용하고, 설치 폴더가 지워지거나 파일이 손상되면 복구한 뒤 앱을 엽니다. 바탕화면 바로가기도 이 복구 BAT를 실행합니다.
- 역할·수신 경로·폴더 확인 여부·수집 개수만 별도 복구 설정으로 보관합니다. 로그인 정보·메일·API 키를 복구 백업에 넣지 않습니다.
- 처리한 연결 확인 요청·응답과 성공 추적 파일을 정리합니다. 전송 프로세스가 사용 중이거나 파일이 잠겨 있으면 다음 확인 때 다시 정리합니다. 오류는 `logs/errors-yyyyMMdd.jsonl`에 단계와 코드로 남깁니다.
- 기존 v18.2 화면과 메일·AI 기능을 유지했습니다.

시작프로그램과 사용자 프로필까지 삭제되는 환경에서는 자동 복구할 수 없습니다. C: 쓰기 권한이 없으면 설치가 실패합니다. 자동 실행을 해제하려면 `Win+R → shell:startup`에서 `EXMail-Recover.bat`를 삭제하세요. Windows 보안 정책은 변경하지 않습니다.

## 소스와 빌드

- `program/`: 실제 배포 소스 35개(복구 모듈 추가)
- `installer/`: 설치·복구 BAT, PowerShell, HTML의 빌드 원본
- `recovery/`: 제공받은 원본 BAT와 v17.2 비교·해시
- `tests/`: 현재 검증과 `legacy-v17.2/`의 원본 QA

Python 3으로 `python tools/build.py`를 실행하면 `dist/`에 설치 HTML, 자동설치 BAT, 프로그램 ZIP, 전체 소스 ZIP과 SHA256 명세가 생성됩니다. 외부 템플릿 다운로드는 필요 없습니다.

UI 검증은 Node.js와 `npm ci` 후 다음 명령으로 실행합니다.

```sh
node tests/first-setup-r1.cjs
node tests/runtime-ui.cjs
```

PowerShell 7에서 복구·정리 로직을 검사할 수 있습니다.

```sh
pwsh -NoProfile -File tests/recovery-cleanup-r1.ps1
```

Linux에서는 XDG_CACHE_HOME, XDG_CONFIG_HOME, XDG_DATA_HOME을 **실제로 존재하는 쓰기 가능한 폴더**로 지정하세요. 최종 배포 HTML에서 추출한 실제 앱의 HTTP·브라우저 검증은 Python `websockets`, Chromium, PowerShell 7이 필요합니다.

```sh
PWSH=/path/to/pwsh python tests/packaged-browser-r1.py
```

## 검증 범위와 제한

설치 폴더 전체 삭제·손상·정상 유지, 설정 복구·백업 제외 항목, 연결 파일 삭제·중복·프로세스 실행 중·파일 잠금 재시도를 시뮬레이션했습니다. 실제 앱 소스를 사용해 설정 시작·취소, 메일 페이징, AI·일정 화면과 최종 패키지 추출 후 HTTP·Chromium 동작을 확인했습니다.

Windows COM 바로가기 생성, 재부팅 자동 실행, i-oneNet 실제 전송, 웹메일 및 AI 계정의 실제 로그인은 Linux에서 실행하지 않았습니다. 해당 부분은 테스트 대역을 사용했습니다. 실제 Windows PC에서 최종 확인이 필요합니다. 기존 v17.2 QA 전체를 통과했다고 주장하지 않습니다.

현재 AI 대화 교환은 기존 RSA/AES/HMAC 방식을 유지합니다. 기존 메일·첨부 교환 전체가 암호화된 것은 아니므로 이 배포를 전 구간 암호화 제품으로 설명하면 안 됩니다.
